# HiLog 通用规则

> 本文档提取自 [DFX Reviewer Skill](./SKILL.md)，包含 HiLog 日志规范中与具体组件无关的通用规则。
> 这些规则来源于 OpenHarmony 日志规范，可被多个审查技能（如 DFX Reviewer、Code Review Checklist 等）复用。

---

## [1] 日志基础规范（HiLog 通用规则）

### 日志级别

**【规则】根据实际情况正确的使用日志打印等级**

| 级别 | 说明 |
|------|------|
| FATAL | 重大致命异常，表明程序或功能即将崩溃，故障无法恢复 |
| ERROR | 程序或功能发生了错误，影响功能正常运行或用户正常使用，可恢复但代价较高 |
| WARN | 发生了较为严重的非预期情况，对用户影响不大，程序可自动恢复或简单操作即可恢复 |
| INFO | 记录业务关键流程节点、可预期的非正常情况（如无网络信号、登录失败）。应由业务内处于支配地位的模块记录，避免在多个被调用的模块中重复记录 |
| DEBUG | 比INFO更详细的流程记录，正式发布版本中默认不打印，仅在调试版本或打开调试开关时打印 |

### 日志内容规则

- [ ] **日志打印内容使用英文描述**，单词拼写无误，符合语法规范
- [ ] **禁止打印隐私信息**：硬件序列号、个人账号、密码、身份等
- [ ] **禁止打印与业务无关的信息**：issue单号、需求单号、公司部门名称、开发人员姓名/工号等
- [ ] **禁止打印重复信息**：不在不同地方打印内容完全一样的日志
- [ ] **禁止在日志打印语句中调用业务接口函数**：日志打印不应影响业务正常流程
- [ ] **禁止将开发调试过程中使用的日志提交到代码仓**：调试日志在提交前必须删除
- [ ] **禁止打印文件名、行号信息**：避免暴露代码内部实现
- [ ] **禁止重复打印TAG信息**：应使用HiLog接口提供的tag参数
- [ ] **日志打印长度不要过长**，尽量控制在一行（100字符左右，不超过160字符）

### 打印时机规则

- [ ] **高频代码的正常流程中禁止打印日志**：被高频调用的接口、大数据量循环、高频中断处理、协议数据流处理、音视频流处理、屏幕刷新处理等
- [ ] **可能重复发生的日志需要进行频率限制**：实施频率限制机制防止大量重复日志
- [ ] **在基本不可能发生的点必须要打印日志**
- [ ] **日志字符串应在日志打印时再生成**：越迟生成越好，日志被关闭时就不会生成字符串

## [2] HiLog API 使用规范

从 OpenHarmony 日志规范中提取的 HiLog API 接口使用规则：

### Domain ID 管理
- [ ] **每个业务须有独立的 Domain ID**：使用 HiLog API 打印日志须先到 DFX 申请标识业务的 Domain ID
- [ ] **禁止使用其他领域的 Domain ID**
- [ ] 系统 Domain ID 范围：`0xD000000~0xD0FFFFF`
- [ ] 测试代码使用专门的 Domain ID：`0xD000F00`
- [ ] Domain ID 为32位整数，以16进制形式表达，分配范围 `0xD0xxxyy`
  - `D0` 为 domain 域标识，`xxx` 高12位为 DFX 分配值，`yy` 低8位业务内部使用
- [ ] 业务内部建议按层次、模块粒度进一步划分 Domain ID

### 日志流量管控
- [ ] **日志服务对每个业务的日志量进行流量管控**，默认每个 Domain ID 的流量阈值是 **10240字节/秒**
- [ ] 修改默认的流量阈值需要经过 DFX 领域评审

### 隐私参数标识
- [ ] **正确填写日志格式化隐私参数标识 `{public}` 和 `{private}`**
  - `{public}`：参数内容以明文输出
  - `{private}`：参数内容以 `<private>` 过滤回显
- [ ] 禁止不分析日志内容随意设置隐私参数标识

示例：
```cpp
// ✅ 正确：设备名称公开，IP地址隐私
HiLog.info(LABEL, "Device Name:%{public}s, IP:%{private}s.", deviceName, ip);
// 输出: Device Name:MyPad001, IP:<private>.

// ❌ 错误：隐私数据标记为public
HiLog.info(LABEL, "Password:%{public}s", password);  // 密码不应公开
```

## [3] 常见模式日志打印检查

从 OpenHarmony 日志规范中提取的各类场景日志记录要求：

### 流程类日志
- [ ] 记录业务的关键流程节点：业务开始点、关键条件分支节点、错误处理点、业务结束点

### 数据库类日志
- [ ] 记录对数据库的各种操作：增、删、改、查
- [ ] 记录操作的发起者、操作类型、操作结果（成功/失败）
- [ ] 操作及返回结果中的内容通常不应记录（防止泄露用户隐私）
- [ ] 查询结果的数量可以打印
- [ ] 性能敏感型业务的数据库操作需记录操作消耗的时间
- [ ] 记录数据库 JOB 信息：名称、执行内容、启动时间、结束时间、执行结果

### 文件类日志
- [ ] 记录对文件的各种操作：创建、打开、读取、写入、关闭、删除、获取属性
- [ ] 记录操作的发起者、操作类型、操作结果
- [ ] 文件内容不可记录（防止泄露用户隐私或暴露系统安全漏洞）
- [ ] 系统文件名可以打印，用户文件名不可以打印
- [ ] 文件句柄值可以打印
- [ ] 批量文件操作只打印一条日志（如批量删除只记录删除的文件数）

### 关键对象/对象池日志
- [ ] 记录关键对象的操作过程、操作结果、状态变化
- [ ] 操作包括：创建、加载、卸载、释放
- [ ] 记录操作主体、操作类型、操作结果
- [ ] 状态类需记录状态变化的前后值

### 线程日志
- [ ] 记录线程的各种操作：创建、启动、暂停、终止
- [ ] 记录操作类型、操作结果、线程号、线程名称（重要线程必须设置线程名）
- [ ] 线程陷入死循环或死锁等错误时要记录日志（需有检测机制）
- [ ] 消息处理型线程打印消息名称、处理结果、处理时长
- [ ] 高频消息只需打印处理结果错误时的日志

### 并发控制日志
- [ ] 记录并发控制对象的操作：创建、占用、释放、等待
- [ ] 记录操作类型、操作对象名称、操作结果、操作位置

### 共享内存日志
- [ ] 记录对共享内存的操作：创建、删除、数据设置、数据查询、销毁
- [ ] 记录操作者、操作类型、操作结果

### 接口交互日志
- [ ] 记录接口交互相关信息：调用者、消息内容（不涉及用户隐私）、处理结果、返回值（不涉及用户隐私）

### 状态机日志
- [ ] 记录状态机的操作：创建、开始、状态转换、结束、销毁
- [ ] 记录状态变化前后的状态名称、导致变化的外部激励条件

### 其他操作系统资源日志
- [ ] Socket：记录连接建立的过程和结果、连接维持情况、连接断开情况及原因
- [ ] 定时器：记录启动、复位、销毁、超时处理过程
