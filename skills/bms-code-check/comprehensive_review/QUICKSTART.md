```
┌─────────────────────────────────────────────────────────┐
│  1. Security Review  →  内存安全、输入验证、权限、并发  │
│  2. Logic Analyzer   →  控制流、数据流、状态机、边界   │
```

## 问题严重等级

| 等级 | 图标 | 是否阻塞 | 示例 |
|------|------|---------|------|
| 致命 | 🔴 | ✅ 是 | 空指针、非法状态转换、死锁 |
| 严重 | 🟠 | ✅ 是 | 权限缺失、错误路径遗漏 |
| 警告 | 🟡 | ⚠️ 视情况 | 日志格式、死代码 |
| 建议 | 🟢 | ❌ 否 | 代码风格、性能优化 |

## 各维度重点速查

### Security Review 重点

```
内存安全
  └─ 空指针解引用
  └─ 缓冲区溢出
  └─ 内存泄漏

输入验证
  └─ 外部数据污染
  └─ 路径穿越
  └─ 注入攻击

权限控制
  └─ 权限校验缺失
  └─ 访问控制不当
  └─ 特权提升风险

敏感信息
  └─ 凭据泄漏
  └─ 日志敏感信息
  └─ 数据未加密

并发安全
  └─ 死锁
  └─ 竞态条件
  └─ 数据竞争
```

### Logic Analyzer 重点

```
控制流
  └─ 死代码
  └─ 逻辑矛盾
  └─ 条件覆盖不完整

数据流
  └─ 未初始化变量
  └─ 数据污染
  └─ 类型不匹配

状态机
  └─ 非法状态转换
  └─ 状态不一致
  └─ 状态机死锁

边界条件
  └─ 数组越界
  └─ 空指针
  └─ 整数溢出

错误处理
  └─ 遗漏错误路径
  └─ 资源泄漏

并发控制
  └─ 死锁
  └─ 竞态条件
  └─ 数据竞争

业务规则
  └─ 不变性破坏
  └─ 契约违反
```

### DFX Reviewer 重点

```
客户端禁令
  └─ frameworks/ 代码禁止打点

场景区分
  └─ boot/settings/api/mdm
  └─ 不同场景不同事件名

事件覆盖
  └─ 所有错误路径
  └─ 成功路径

错误报告
  └─ 包含上下文
  └─ 具体的错误码

数据隐私
  └─ 敏感数据匿名化

HiTrace使用
  └─ >10ms 操作需要 trace
```

### Code Review Checklist 重点

```
兼容性
  └─ API 破坏性变更
  └─ 错误码变更
  └─ 性能劣化

日志规范
  └─ 格式: who do what
  └─ 高频代码禁止日志
  └─ 不可能发生点必须日志

安全编码
  └─ 指针使用
  └─ 类型安全
  └─ 数组安全
  └─ 内存管理

常见陷阱
  └─ Pitfall 1: SA初始化阻塞
  └─ Pitfall 2: 数据一致性
  └─ Pitfall 3: 敏感数据保护
  └─ Pitfall 4: 错误码处理
  └─ Pitfall 5: SA启动流程
  └─ Pitfall 6: 锁性能
  └─ Pitfall 7: IDL接口顺序
```

## 修复优先级

### P0: 立即修复 (1-2天)
- 🔴 所有致命问题
- 影响: 系统安全性、稳定性
- 阻塞: 上库

### P1: 本周修复 (5-7天)
- 🟠 所有严重问题
- 影响: 功能正确性、安全性
- 建议: 强烈修复

### P2: 逐步优化 (3-5天)
- 🟡 警告问题
- 🟢 建议优化
- 影响: 代码质量
- 建议: 可选

## 常见问题速解

### Q: 如何快速判断是否可以上库？
**A**: 查看Summary部分：
- 🔴 高风险 → ❌ 不要上库
- 🟠 中风险 → ⚠️ 评估后决定
- 🟡/🟢 低风险 → ✅ 可以考虑

### Q: 发现致命问题怎么办？
**A**:
1. 立即修复
2. 添加单元测试
3. 重新检视
4. 验证通过

### Q: 误报怎么处理？
**A**:
1. 在代码中添加注释说明
2. 在报告中标记为误报
3. 更新检查规则避免再次误报

### Q: 如何减少检查时间？
**A**:
1. 小型变更：快速检查模式
2. 只检查关键维度
3. 增量检查（只检查变更部分）
